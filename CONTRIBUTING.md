# Contributing

Thank you for your interest in contributing to this project! Contributions, improvements, and suggestions are welcome.

* **Fork the repository** and create your own copy of the project.
* **Create a new branch** for your changes.

  * Use descriptive names such as `feature/add-auto-completion` or `fix/animation-stuck`.
* **Keep changes focused** on one feature, bug fix, or improvement per pull request.
* **Follow the existing code style** and project structure.
* **Write clean and readable code** with meaningful variable, function, and class names.
* **Add or update documentation** when your changes introduce new features or behavior.
* **Test your changes** before submitting a pull request.
* **Do not commit** passwords, API keys, tokens, `.env` files, or other sensitive information.
* **Write clear commit messages** that briefly describe what was changed.
* **Push your branch** to your forked repository.
* **Open a Pull Request (PR)** against the project's `main` branch.
* In the PR description, **explain what you changed and why**.
* If your PR fixes an issue, **reference the related issue** when applicable.
* Be respectful and constructive when reviewing or discussing contributions.
* Maintainers may request changes before a PR is merged.
* Contributions are reviewed and merged at the maintainers' discretion.

## Pull Request Checklist

Before submitting a pull request, make sure:

* [ ] The code builds successfully.
* [ ] The changes have been tested.
* [ ] Existing functionality has not been unnecessarily broken.
* [ ] Documentation has been updated where necessary.
* [ ] No sensitive information has been committed.
* [ ] Commit messages are clear and meaningful.
* [ ] The PR clearly explains the changes.
